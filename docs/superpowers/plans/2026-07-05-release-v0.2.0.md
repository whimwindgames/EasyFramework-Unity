# EasyFramework v0.2.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to run this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. **This plan must run last**, after `2026-07-05-framework-polish-improvements.md`, `2026-07-05-content-update-service.md`, and `2026-07-05-network-and-multiplayer.md` are all implemented, tested green, and committed.

**Goal:** Bump `com.yifei.easyframework` to `0.2.0`, document the new capabilities in `CHANGELOG.md`, and publish the release so OpenUPM picks it up.

**Architecture:** Version has a single source of truth (`package.json`). Publishing is git-native: OpenUPM watches the public `github` remote (`whimwindgames/EasyFramework-Unity`) and rebuilds automatically off a semver tag — there is no separate "OpenUPM push" command, the tag *is* the publish action. This repo has two remotes (`github` = public distribution, `origin` = private working repo); only `github` matters for OpenUPM.

**Tech Stack:** git, semver, OpenUPM (passive consumer of GitHub tags).

```markdown
## [0.2.0] - 2026-07-05

### Added

- `IContentUpdateService`:基于 Addressables 官方 Remote Content Update 机制的资源热更新服务,启动时静默检查、`ContentAvailableEvent` 通知业务层决定是否下载,`G.ContentUpdate` 挂载。
- `IHttpService`:通用 HTTP 基础设施(GET/POST、超时、重试、JSON 序列化走 Newtonsoft),`G.Http` 挂载。
- `IMultiplayerService` / `IMultiplayerProvider`:可选联机适配层,只定义连接生命周期契约,不内置任何传输协议;不进 `FrameworkInstaller`/`G`,由需要联机的具体游戏自行注册实现。
- `IEventBus` 递归深度保护,防止事件互相触发导致的死循环拖垮主循环。
- `GameBootstrap` 逐任务耗时日志(开发模式下超阈值打印),便于定位启动变慢的具体 `IBootTask`。
- `PoolService` 支持按 key 配置闲置超时自动销毁(默认关闭,不影响现有行为)。
- 本地化编辑器批量漏翻译检测工具。
- `AudioService` 同音效并发限流,避免高频触发同一音效造成音量堆叠。

### Notes

- 明确不引入代码热更新(HybridCLR 等):经评估违反 Apple App Store Review Guideline 2.5.2,存在开发者账号级别的下架风险,风险与收益不成比例(详见 `docs/superpowers/specs/2026-07-05-content-update-service-design.md` 背景说明)。
```

### Task 5: Tag and publish

**Files:** none (git operations only)

This task pushes to the **public** GitHub remote (`github` → `whimwindgames/EasyFramework-Unity`) and creates a tag that OpenUPM will automatically build and publish to every consumer of `com.yifei.easyframework`. This is a one-way, publicly visible action.

- [ ] **Step 1: Confirm the remotes before doing anything**

```bash
git remote -v
```

Expected: `github` points to `https://github.com/whimwindgames/EasyFramework-Unity.git` (public distribution repo) and `origin` points to the private working repo. Double-check you are tagging/pushing to `github`, not `origin`.

- [ ] **Step 2: STOP — confirm with the project owner before proceeding**

Do not run Step 3 or Step 4 without an explicit go-ahead in that conversation, even if this plan was pre-approved. Publishing a new package version is irreversible (consumers' package managers will pick it up automatically) and affects everyone using `com.yifei.easyframework`, not just this repo. State clearly what is about to happen (branch being pushed, tag name, that OpenUPM will auto-rebuild) and wait for confirmation.

- [ ] **Step 3: Push the branch and create the tag**

```bash
git push github develop
git tag v0.2.0
git push github v0.2.0
```

Expected: tag `v0.2.0` appears on `https://github.com/whimwindgames/EasyFramework-Unity/tags`.

- [ ] **Step 4: Verify OpenUPM picks up the new version**

OpenUPM rebuilds automatically off the tag; this typically takes a few minutes to a few hours. Check `https://openupm.com/packages/com.yifei.easyframework/` and confirm `0.2.0` is listed. This step cannot be rushed or automated further — it is an external, asynchronous process outside this repo's control.
